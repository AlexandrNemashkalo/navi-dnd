# Разработка NaviDnD

## Запуск из исходников

1. Установи [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0) и один из клиентов: [Codex CLI](https://developers.openai.com/codex/cli) или [Claude Code](https://code.claude.com/docs/en/quickstart). Нужен аккаунт с доступом к выбранной нейронке.
2. Скачай репозиторий и открой PowerShell в его папке.
3. Собери игру и сервер инструментов:

   ```powershell
   dotnet build NaviDnD.McpServer/NaviDnD.McpServer.csproj
   ```

4. Запусти игру в отдельном окне консоли:

   ```powershell
   Start-Process .\NaviDnD\bin\Debug\net9.0\NaviDnD.exe
   ```

5. В меню **Настройки** выбери нейронку. Укажи путь к её exe, если она не найдена в PATH, и доступные твоему аккаунту модели игры, мира и героя.
   - **Codex:** один раз выполни `codex login`. Отдельный токен в игре не нужен. Начни с Sol 6.1 и среднего размышления, если модель доступна аккаунту.
   - **Claude:** войди через `claude auth login` и оставь поле токена пустым либо получи токен по инструкции ниже.
6. Выбери **Новая игра** и создай персонажа.

Папки хранения и файл настроек создаются автоматически при первом запуске; сохранения, миры и герои — по мере игры. Данные находятся в `NaviDnD/Storage/`, логи — в `NaviDnD/logs/`. Обе папки исключены из Git. Перед пересборкой закрой игру. Обновление исходников — `git pull` и повторная сборка.

### Alacritty на Windows

На Windows игра по умолчанию запускается в GPU-терминале [Alacritty](https://alacritty.org/). Нужен Windows 10/11 с ConPTY. В релизе терминал уже включён; при сборке из исходников установи Alacritty или положи portable `alacritty.exe` рядом с `NaviDnD.exe`. Также поддерживается PATH или полный путь в `NAVIDND_ALACRITTY_PATH`.

```powershell
# Если Alacritty не установлен и используется portable-версия:
$env:NAVIDND_ALACRITTY_PATH = 'C:\Tools\Alacritty\alacritty.exe'
.\NaviDnD\bin\Debug\net9.0\NaviDnD.exe --alacritty
```

Для прежнего запуска в классической консоли используй `--classic-console`; UI-тесты с `NAVIDND_TEST_WORLDSTATE` сохраняют классический хост, если явно не задан `--alacritty`. Режим не меняет системный терминал и личный конфиг Alacritty; используется `Terminal/alacritty-windows.toml` рядом с exe. Хранилище игры остаётся прежним.

Размер сетки — 150 × 63. Окно без системного заголовка: свернуть, переключить полный экран и закрыть можно кнопками внутри игры; верхняя рамка позволяет перетаскивать окно. Полный экран сохраняет размеры сетки и центрирует игру на однотонном фоне. В конфиге оставлено `decorations = "Full"`, а видимую рамку убирает сама игра: режим `None` уменьшает сетку Alacritty при сворачивании и портит изображение после восстановления. Consolas 10 pt с межстрочной поправкой −1 даёт ячейку 7 × 14 при масштабе Windows 100% — пропорции 1:2, на которые рассчитаны картинки. Масштаб меняется средствами Alacritty (`Ctrl` + `-` / `+`); при другом размере шрифта или DPI пропорции могут отличаться. Если сетка не помещается, игра покажет подсказку. Настройки шрифта старой консоли в этом режиме скрыты. Вывод буферизуется, курсор отслеживается локально, ввод клавиатуры и мыши проходит через общий VT/SGR-обработчик. Реальные запросы ИИ от смены терминала быстрее не становятся.

### macOS и Linux

Игра работает в терминале. Подойдут iTerm2, Ghostty, kitty или WezTerm: они сообщают о движении мыши, от которого зависят наведение и пути. В Terminal.app от Apple играть можно с клавиатуры.

```bash
brew install --cask dotnet-sdk        # или установщик .NET 9 SDK от Microsoft
dotnet build NaviDnD.McpServer/NaviDnD.McpServer.csproj
dotnet NaviDnD/bin/Debug/net9.0/NaviDnD.dll
```

- **Размер окна.** Раскладка — фиксированная сетка примерно 150 × 63 символа. Игра просит терминал увеличиться; если он не может, игра ждёт с сообщением, пока окно не станет достаточно большим: увеличь его или уменьши шрифт (Cmd −).
- **Функциональные клавиши.** F1–F12 переключают вкладки. На клавиатуре Mac держи Fn или включи «Системные настройки → Клавиатура → Использовать F1, F2 и т.д. как стандартные функциональные клавиши». В iTerm2 проверь, что клавиши ни на что не назначены.
- **Option как Alt.** Alt+стрелки листают карточки и диалог: клавиша Option должна отправлять Esc+ («Use Option as Meta key» в Terminal.app).
- **Из исходников на macOS нет** кнопок окна, настроек шрифта и автообновления — окном и шрифтом владеет терминал, обновление — `git pull` и пересборка. Готовое приложение (`NaviDnD.app`, см. «Сборка для macOS») умеет всё это само.
- `NAVIDND_MUTE=1` выключает весь звук — удобно при разработке, особенно с `NAVIDND_TEST_WORLDSTATE`, который не читает настройки игрока.

На macOS/Linux `UnixTerminal` берёт терминал под себя (сырой ввод, мышь SGR, альтернативный экран) и выдаёт те же записи ввода, что и консоль Windows, поэтому у экранов один путь ввода; остальная игра работает с терминалом через `Term`. Звук на macOS — AudioToolbox (`AudioQueuePlayer`), картинки на всех ОС рисует SkiaSharp. Порт на macOS сделал [Keyton Weissinger](https://github.com/Brightwing-Systems-LLC/navi-dnd).

### Поиск клиентов

При каждом запуске игра ищет клиенты в фоне: PATH, стандартные папки, npm и расширения VS Code, Cursor и Windsurf. Устаревшие пути исправляются автоматически, работающие ручные пути сохраняются; меню не ждёт завершения поиска. Если найден только Codex, он будет выбран автоматически. Начальные модели: Codex — Sol 6.1 со средним размышлением, Claude — Opus 5.5.

### Токен Claude для настроек игры

1. Установи [Claude Code](https://code.claude.com/docs/en/quickstart). Для токена нужна подписка Claude Pro, Max, Team или Enterprise.
2. Выполни в PowerShell `claude setup-token`. Если команда не найдена, укажи путь к exe: `& "C:\путь\к\claude.exe" setup-token`.
3. Открой предложенную ссылку, войди в аккаунт Claude и подтверди доступ. Если браузер покажет код подтверждения, вставь его в терминал.
4. Скопируй OAuth-токен. В игре открой **Настройки**, выбери **Claude** и вставь его в поле **Токен Claude**.

Ключ API из Anthropic Console сюда не подходит. Токен хранится локально в `Storage/settings.json`, исключённом из Git. Если токен истёк, снова выполни `claude setup-token`. [Официальная инструкция](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token).

## Озвучка Silero

В готовой сборке Silero, русская модель, Python и CPU PyTorch включены в установщик; комплект находится в `Speech/silero/`. Для запуска из исходников без комплекта нужен Python 3.10–3.12 x64; установка: `powershell -NoProfile -ExecutionPolicy Bypass -File NaviDnD/Speech/setup-silero.ps1`. На macOS/Linux (Python 3.10–3.12, например `brew install python@3.12`): `bash NaviDnD/Speech/setup-silero.sh` — игра запускает его сама при первом включении озвучки. Для сборки автономного релиза кэш Silero должен использовать Python 3.12. Используется [Silero v5.5](https://github.com/snakers4/silero-models).

При включённой озвучке ведущий передаёт один `text` с SSML-разметкой: на экране игра скрывает теги, ударения и смысловые выделения, а Silero получает паузы и настройки интонации. Флаг `speechEnabled:true/false` передаётся одной строкой в контексте; при выключенной озвучке ведущий присылает обычный текст. Если разметка некорректна, используется обычная речь. При запуске с включённой озвучкой модель загружается и прогревается в фоне без звука. Если звука нет, проверь статус в настройках и `logs/speech.log`.

## Проверка кода

```powershell
dotnet test NaviDnD.Tests/NaviDnD.Tests.csproj
```

Не запускай тесты всего решения без необходимости: `NaviDnD.PromptTests` делает реальные запросы к нейронке и расходует лимиты/средства. Подробнее о Codex: [codex.md](codex.md).

## Языки

Текст на экране — через `L.T("English source text")`, с подстановками — `L.F("Day {0}", day)`; текст, который сохраняется или уходит мастеру на языке игры (история, названия генератора), — `L.W`/`L.WF`. Русский перевод — в `NaviDnD.Data/Localization/ru.json` с тем же английским ключом; строка установщика — ещё и в `NaviDnD.Installer/ru.json`. Служебные инструкции мастеру пишутся по-английски без `L`. `LocalizationTests` показывает строки без перевода. Подробности и границы — [localization.md](localization.md).

## Формат сохранений и миграции

У файлов данных (сохранения, заметки, карточки героев, миры с локациями) есть поле `formatVersion` — `StorageFormat.Current`. Меняешь, как данные лежат в файле (переименование поля, новые значения-ключи, перенос), — увеличь `StorageFormat.Current` и добавь шаг в `NaviDnD/Migrations/StorageMigration.cs` (из версии N в N+1, над JSON), с тестом в `StorageMigrationTests`. Код игры читает только текущий формат.

Шаги выполняет `NaviDnD.exe --migrate <папка игры>`: его запускает помощник обновления после патчей; при запуске из исходников — сама игра при старте (или вручную после `git pull`). Перед записью — копия файлов в `Storage/Backup/format-<N>-<время>`; лог — `logs/migrations.log`.

## Обновления

Готовая сборка проверяет новую версию в фоне при запуске; вручную — **Обновления** в главном меню. После проверки SHA256 игра закрывается, обновляется без отдельного окна установщика и запускается снова. Сохранения, настройки и модель Silero сохраняются. Логи — `logs/updates.log`.

Начиная с 1.1.5 обновления приходят **патчами**: скачиваются только изменённые файлы. Перед применением игра проверяет SHA256 скачанного и все файлы установленной версии; патч применяет помощник `Updater/NaviDnD-Setup-win-x64.exe` (копия установщика, ставится вместе с игрой). Замена идёт с резервом: при любой ошибке прежние файлы возвращаются. Если файлы игры повреждены или версия слишком старая, игра скачивает полную базовую сборку и патчи к ней.

**Переход на патчи (версии до 1.1.4 включительно).** Старая игра патчей не понимает и обновляется полной сборкой (около 500 МБ). Новый установщик ставит её, докачивает патчи и ставит помощника. Если переход сорвался, игра останется на базовой версии 1.1.4 и предложит обновиться снова.

Файлы `NaviDnD-payload.*` — части базовой сборки (игра, .NET и озвучка Silero), разделённые из-за лимита размера файлов. Установщик ставит базу и доводит её до актуальной версии патчами из `releases/patches/`; если их рядом нет — скачивает из последнего релиза.

## Публикация новой версии

Измени `Version` в `Directory.Build.props`, закоммить исходники, запусти `build-release.ps1`, закоммить `releases/` и `.gitlab/release.json`, затем отправь коммит и тег `v<версия>`. GitLab CI создаст релиз со ссылками на базу, установщик и патчи. Для обновлений без авторизации проект должен быть публичным.

`powershell -NoProfile -ExecutionPolicy Bypass -File build-release.ps1`:

- **без ключей — патч-релиз** (обычный случай). Игра и MCP-сервер собираются заново и сравниваются с описанием файлов предыдущей версии (`releases/manifests/<версия>.json`); в `releases/patches/` появляется `NaviDnD-patch-<было>-<стало>.zip` только с изменёнными файлами, списком удалённых и полным списком исходных файлов с SHA256. База (`NaviDnD-payload.*` с .NET и Silero) не пересобирается и не отправляется заново — ссылки ведут на тег, где она опубликована. Установщик пересобирается, только если изменились его исходники (`NaviDnD.Installer`), — поэтому их нужно закоммитить до сборки. Цепочка патчей описана в `releases/NaviDnD-updates.json`, а `SHA256SUMS.txt` остаётся в старом формате для клиентов до 1.1.4;
- `-Base` — новая полная база с Silero (когда меняется озвучка или патчи стали слишком большими): части архива, установщик, описание файлов, цепочка патчей с нуля;
- `-AdoptBase` — объявить базой уже собранные части без пересборки (так 1.1.4 стала базой для патчей).

### Сборка для macOS

`build-release.ps1` вызывает `build-macos.ps1` (без него — ключ `-NoMac`): у Mac своя цепочка в `releases-macos/` (вне `releases/`, чтобы архив «все файлы установки» для Windows не рос). Первый раз собирается база, дальше — патчи. Упаковка выполняется на Windows; собственный Alacritty со сменой указателя предварительно собирается на Mac: `bash macos/build-alacritty.sh`. Перенеси папку `artifacts/macos-cache/alacritty-custom` на сборочную машину. Версии, хеши и проверка описаны в [macos/ALACRITTY.md](../macos/ALACRITTY.md). Без проверенного бинарника упаковка завершается до сборки приложения.

- **база** (`build-macos.ps1 -Base`) — приложение `NaviDnD.app` (см. ниже). Архив `artifacts/NaviDnD-macOS-arm64-<версия>.zip` разрезается на `releases-macos/NaviDnD-macOS-payload.*`; на теге CI склеивает их и выкладывает в Package Registry — ссылка «Скачать для macOS» в релизе ведёт туда;
- **патч** (без ключей) — `releases-macos/patches/NaviDnD-macOS-patch-<было>-<стало>.zip`, цепочка — в `releases-macos/NaviDnD-macOS-updates.json`. На Mac патчи ставит сама игра (меню «Обновления»): проверка SHA256, замена с откатом, перезапуск в том же окне; патч обновляет приложение целиком, вместе с подписью (`versionFile` в `patch.json` — `Contents/Resources/release-version.txt`); повреждённая установка — полная база и патчи;
- `-Test` — только архив в `artifacts/` для проверки, `releases-macos/` не трогается.

**NaviDnD.app** — по правилам Apple. `Contents/MacOS` — только программы: игра и MCP-сервер `osx-arm64` одним файлом каждый (.NET внутри), библиотеки SkiaSharp/HarfBuzz и терминал [Alacritty](https://alacritty.org) 0.17.0 с локальным патчем OSC 22 (Apache 2.0). `Contents/Resources` — файлы игры (`AppConfig.ProjectRoot`), значок `macos/NaviDnD.icns` (эмблема ярлыка Windows), настройки терминала `macos/alacritty.toml`, лицензия Alacritty. Озвучка (свой Python 3.12 и PyTorch, `macos/silero-requirements.txt`, версии и хеши закреплены) лежит архивом `Speech/silero.zip`: папки Python (`python3.12`, `*.dist-info`) подпись принимает за вложенные приложения; игра распаковывает его в фоне при первом запуске и после обновления (`SileroSpeech.UnpackBundledAsync`). Сохранения, настройки и логи — в `~/Library/Application Support/NaviDnD` (`AppConfig.DataRoot`): приложение заменяется целиком.

Finder запускает игру без терминала — `MacApp.Launch` заменяет процесс терминалом Alacritty, а в нём игра запускается снова с `--navidnd-terminal`. Шрифт — Menlo, размер — из настроек («авто» — самый крупный, что помещается). Весь экран (по умолчанию) — терминал на весь экран, игра сама встаёт по центру его сетки (`UnixTerminal`: сдвиг вывода и мыши), строки под вырезом экрана MacBook пропускает (`--navidnd-top`, безопасная зона `NSScreen`), вокруг — фон игры. В окне — окно ровно 150 × 63 по центру, без кнопок macOS, перетаскивается за верх (`Buttonless`). Режим окна и размер шрифта Alacritty меняет только при запуске — смена в настройках перезапускает окно и возвращает на тот же пункт (`MacApp.Relaunch`). Кнопки игры: «свернуть» скрывает приложение, «закрыть» — выход; кнопки «весь экран» нет. Собственная сборка Alacritty поддерживает курсор-руку через OSC 22; запрет растягивать окно остаётся недоступен.

Приложение подписывается при сборке локальной подписью (`rcodesign`): без подписи macOS называет скачанное приложение повреждённым, а подпись на Mac изменила бы файлы и сломала проверку патчей. Подпись одинакова при каждой сборке, поэтому сборка всегда полная, а в патч попадает только изменившееся. Загрузки Python, модели, лицензии Alacritty и rcodesign — с закреплёнными версиями и хешами, кеш — `artifacts/macos-cache`. Для собственного Alacritty отдельно проверяются исходный коммит, версия Rust, хеш патча, архитектура и хеш бинарника.

Установка для игрока: распаковать архив, перетащить `NaviDnD` в «Программы» и открыть. macOS один раз попросит разрешение: «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть». Открытое прямо из «Загрузок» приложение macOS запускает из временной копии — игра находит настоящее (`SecTranslocateCreateOriginalPathForURL`), снимает с него карантин загрузки и открывает его.

Игровые данные не включаются; ресурсы берутся только из файлов, отслеживаемых Git. Исходники и релиз хранятся в одном репозитории. Проверка без окна: `NaviDnD-Setup-win-x64.exe --extract <папка>` ставит базу, `--apply-patches <папка> <папка с патчами>` применяет цепочку.

Промежуточные файлы релиза создаются в системной временной папке и автоматически удаляются после сборки, в том числе при ошибке.
