# Архитектура NaviDnD

При `plan_location` открытые локации получают тихие природные окраины вокруг авторского плана, если они помещаются вместе с этажами в поле. Окраины сразу отмечаются заполненными: отдельный запрос мастеру для них не нужен. Геометрия сохраняется обычным снимком карты; существующие локации не пересоздаются.

`GameWorld.SiteAt` учитывает дороги (включая тропы хроники) и реки в текущей и соседних кардинальных клетках мира. Смещение относительно поселения и направления дорожных подходов передаются генератору. Это локальное приближение географии, а не точная масштабная копия мира. Свободный сухой край не закрывается искусственной чащей: шаг наружу вне боя предлагает переход на карту мира; стены, скрытые двери, вода и скалы сохраняют ограничения.

Консольная ролевая игра с ИИ-мастером для Windows и macOS (Linux — из исходников). Правила D&D 5e задаются промптами; движок отвечает за состояние, геометрию, отображение и взаимодействие с игроком.

## Анимации интерфейса

`AnimationLoop` обновляет независимые анимации по монотонным часам. У каждого кадра своя длительность: кубик сохраняет паузу после каждого кадра (`catchUp: false`) и стартует после запуска звука; текст — режим `catchUp: false` с паузой 40 мс после символа, чтобы после задержки не печатать накопившиеся символы рывком. `Start` регистрирует параллельные анимации, `PlayAsync` ожидает последовательность, `DelayAsync` обновляет анимации и опрашивает ввод. Обработчики кадров выполняются синхронно из `Tick`: нельзя запускать фоновые записи в консоль или блокировать обработчик ожиданием ввода. Регистрацию нужно освобождать при закрытии экрана.

Диалог использует общий цикл для текста, спиннера, кубика и движения. Спиннер обновляет только нижнюю область; диалог пропускает неизменившиеся строки. Перетаскивание карты и окна обрабатывается при опросе ввода, без вложенных блокирующих циклов. Движения мыши объединяются в один кадр; при перетаскивании обновляется только поле карты, легенда — после отпускания. `AnsiColorRuns` сокращает повторные команды цвета в буфере карты. Порядок применения игровых патчей сохраняется.

`ConsoleRegionBuffer` хранит отдельные кэши строк текста и картинки; наведение обновляет только затронутые клетки, легенду и картинку. `SvgToBrailleConverter.PrepareAsync` готовит изображения в фоне; применение и вывод остаются в UI-цикле. Достижимость клеток для пути под курсором кэшируется до изменения состояния карты или героя.

## Проекты

Все .NET-проекты, решение `NaviDnD.slnx`, общие настройки `Directory.Build.props` и ресурсы `GameData/`, `icons/` находятся в `src/`; файлы платформы macOS — в `src/macos/`. Общие сборочные скрипты находятся в `scripts/`; документация, релизы и `artifacts/` — в корне репозитория. При публикации `src/` в пакет игры не попадает.

| NaviDnD | Игровой цикл, UI, хранилище, клиенты ИИ |
| NaviDnD.Launcher | Windows-запускатель Alacritty без промежуточной консоли; используется ярлыками и панелью задач |

## Игровой поток

`Program` загружает настройки, создаёт каталоги хранения и собирает `Storage`, `GameAiClient` и экраны. `MapScreenLoop` обрабатывает игру; `MovementHandler` выполняет движение и обнаруживает триггеры. Обычная ходьба не требует вызова модели.

`GameAiClient` выбирает промпт действия и контекст из `AiContextBuilder`. `SwitchableAiProvider` выбирает Claude или Codex по текущим настройкам. `AiActionTools` задаёт инструменты действия и путь состояния для MCP. Создание героя и старт используют черновик; обычные ходы — активное сохранение.

Мастер возвращает JSON с патчами и `history`. `SequentialHistoryPlayer` применяет корневой патч, затем последовательно показывает записи, анимирует `movePath` и применяет вложенные `patch`. Броски, реакции и выбор цели проходят через MCP и файловые запросы к UI; старый маркер `triggerReaction` не является текущим протоколом.

Патч отдыха применяется в соответствующей записи `history`, после предыдущих изменений времени. `long_rest` / `short_rest` принимают необязательный `elapsedDays`: целые дни, уже прошедшие в текущем ответе, но ещё не применённые к сохранению (например, обход при путешествии). Дни маршрута, уже списанные движком, повторно не передаются; формат сохранения не меняется.

`narrative.npcs.gender` содержит ключ `male`/`female`, если пол известен. Движок один раз назначает `speechVoice` (язык, speaker Silero, pitch) и сохраняет его; патчи мастера это поле не меняют, в MCP-контекст оно не передаётся. Озвучка ищет NPC по имени автора без учёта регистра и пробелов по краям. SSML voice и pitch модели не меняют закреплённый голос; рассказчик сохраняет выбранный голос и низкий тон. Формат 3 добавляет миграцию назначений старым NPC. При неизвестном поле gender голос выбирается из общего набора; после назначения он закреплён.

`NpcPortraits` закрепляет за NPC лицо из локальной галереи: `narrative.npcs.portrait` хранится в сохранении, исключается из контекста MCP и не меняется патчами мастера. Карта и журнал используют одно лицо; NPC без записи журнала получает его в существующем `map.entities.image`. Известные семейства спрайтов и группы портретов задаёт манифест правил, текст описания для угадывания расы не разбирается. Пользовательские портреты и изображения монстров сохраняются. Формат 4 добавляет пустое поле старым записям с резервной копией; назначение выполняется после загрузки библиотеки, без вызова модели.

`CatalogSearch.IconsFor` использует категорию из запроса либо категорию сущности, заданную движком, как одинаковое ограничение поиска. Для зелий, книг, свитков, колец, амулетов и жезлов в game-icons дополнительные слова цвета/материала не могут заменить тип предмета: результаты фильтруются по названиям подходящих форм, затем используется общий рисунок категории. Это ограниченный словарь форм, не полноценная семантическая разметка всего каталога; цвет общей иконки не гарантируется.

Если точная фраза и её варианты не найдены, запасной поиск пробует слова английского названия справа налево, начиная с вероятного главного существительного. Обороты `of/with/in/on/for/holding/carrying/wearing` проверяются после основной части: «weathered pouch of coins» сначала ищет сумку, «goblin with spear» — гоблина. Это эвристика для коротких запросов к иконкам, не языковой анализ; явные варианты через запятую и точные составные названия сохраняют приоритет.

`Speech` озвучивает новые записи истории и реплики MCP через локальный Silero в отдельной ограниченной очереди. Синтез и аудио не блокируют UI; Enter, Esc и F11 отменяют текущую речь и очередь. Настройки включения, громкости, голоса и пути Python сохраняются только у игрока. Готовая сборка содержит переносимый Python, CPU PyTorch и модель в `Speech/silero/`: скачивание при включении не требуется. Комплект готовит `scripts/prepare-silero-bundle.ps1`; личные файлы из Storage не копируются. При запуске из исходников без комплекта сохраняется установка в `Storage/Speech/silero/` через `setup-silero.ps1`. Озвучка по умолчанию выключена. `SileroSpeech` управляет Python-процессом через JSON-lines: `silero_worker.py` загружает модель один раз и создаёт WAV для каждой реплики. Отмена во время синтеза завершает процесс; следующая реплика загрузит его заново.

## Состояние и патчи

Пол именованного NPC передаётся и в `map.entities.gender` (`male|female`, неизвестный — `null`), чтобы портрет можно было выбрать до появления записи в журнале. Формат 9 переносит в сущность только явный факт из журнала, не угадывая его по имени или прозе. При появлении известного пола несовместимое каталожное лицо заменяется согласованным; пользовательские файлы и портреты не заменяются. Новый NPC без пола получает только неразмеченное лицо или исходный спрайт. Исправленные метаданные каталога применяются и к ранее назначенным лицам.

Вступление задаёт ситуацию и местные интересы без обязательного боя и принятого задания. `plotThreads.status` хранит стабильные ключи `rumor`, `offered`, `active`, `revealed`, `completed`, `failed`; согласие на задание по-прежнему определяет мастер по действиям игрока. Журнал различает слух, предложение и принятую цель, локализует подписи и ставит принятые цели первыми. Произвольные статусы сохраняются дословно и показываются нейтрально; отсутствие статуса не означает принятие. Формат 8 нормализует только известные точные варианты с резервной копией. Неизвестные линии остаются `hidden:true`, намерения и место действия записываются в `dmNotes`, `currentArc` содержит только выбранную героем цель. AI/MCP получают ключи и прежние ID записей.

`AiContextBuilder.SceneMemory` без запросов модели выбирает до двух видимых или названных в действии NPC и до трёх связанных сюжетных линий по текущему месту, участникам, названию в действии или выбранной цели героя. Сопоставление учитывает границы имён. Дополнительный блок ограничен 2400 символами, сохраняет исходные индексы для патчей и помечен как сведения мастеру; полные записи доступны через MCP. Блок `World memory` отдельно передаёт до 1900 символов хроники: правила и историю мира, сведения о текущем обществе и месте; он используется также при наполнении блоков. Оба блока — выборка существующих фактов, не фоновая симуляция и не доказательство знания героя. Наполнение блоков карты больше не требует обязательных групп врагов.

`NarrativeRecall` ограничивает индексы кампании 24 записями каждого типа и тело памяти для `PopulationState` 6500 символами. Приоритет получают названные участники, текущая цель, место и редкие общие слова; это эвристический поиск, а не гарантия полноты. Усечённые записи и число пропусков явно отмечены, сохранения не сокращаются. MCP принимает исходный ID (`narrative.plotThreads:#7`) и поиск по полному тексту (`narrative.npcs:~ключ`), включая память и скрытые заметки; возвращает все совпадения без усечения с исходными ID. Повторные фильтры одного поля объединяются, пустой фильтр возвращает пустой список, поле без фильтра явно запрашивает весь массив. Удалённые записи исключены; портреты и настройки голоса не участвуют в поиске.

`history[].text` может содержать SSML `<speak>`. `Speech.DisplayText` готовит обычный экранный текст, сохраняя механику в `[...]`; `Speech.ValidateSsml` оставляет разрешённую разметку и исключает механику из озвучки. `DialogMessage.SpeechText` — локальная производная копия для речи, не отдельное поле ответа модели. Преобразование выполняется в `Storage.ApplyUpdateWorldState`, `SequentialHistoryPlayer` и потоке MCP-истории. `AiContextBuilder` возвращает модели только очищенную историю. `Speech.Initialize` заранее ставит в очередь тихий прогрев Silero, не блокируя меню.

`WorldState` хранит героя, карту, историю, время, бой, сюжет и связь с миром. `CellEntity` задаёт объект карты, `LivingEntity` добавляет хиты и эффекты, `Hero` — характеристики, ресурсы, действия и снаряжение. JSON использует camelCase; чтение регистронезависимое.

`Storage.ApplyUpdateWorldState` применяет изменения. Для коллекций с `PatchByIndex`:

- `id` — индекс текущего списка; без `id` элемент добавляется.
- Существующий индекс обновляет только переданные поля; новый индекс добавляет элемент.
- `deleted: true` удаляет элемент, если коллекция допускает удаление; удаления выполняются с конца списка. Существа карты сохраняются с пометкой `deleted`, чтобы последующие патчи истории по id не меняли адресата; хиты и остальные поля того же патча применяются до создания тела.
- Механизм используется для характеристик и ресурсов героя, комнат, существ и объектов. Устаревшее правило «заменить эти списки целиком» неверно.
- Изображения обновляются по `key`. Остальные поля обрабатываются своими `Apply*`; точный контракт находится в `Storage.cs` и промптах.

Координаты тактической карты — `[col, row]`, начиная с 1; символы сущностей — три знака. Для патчей по индексам мастер получает данные через `get_world_state`; ключи и фильтры определяются `WorldStateTools` и `AiContextBuilder.Serialize`.

`door_action` принимает необязательный `entityId`: `-1` — герой, иначе исходный индекс NPC на карте. Открытие, закрытие и разрушение требуют позиции именно действующего персонажа на `From` или `To`; удалённый NPC, отсутствующий ID и NPC с нулевыми хитами получают отказ. Инструмент возвращает патч, не записывает состояние и не перемещает персонажей. Выходы на карту мира остаются защищены. Это позволяет смотрителю открыть дверь самому, не требуя от героя занять его место.

Инструменты отдыха используют существующую локальную шкалу: 3600 шестисекундных раундов на часть суток; короткий отдых добавляет 600, долгий — 4800. При переносе часов через часть суток одним патчем перебазируются сроки героя, NPC, предметов, объектов и событий. Длительные эффекты сохраняются; истёкшие эффекты без callback удаляются, герой/NPC/объекты карты с `onExpire` остаются для `RoundBundle`, предметы инвентаря с `onExpire` разрешает мастер. `Storage` распознаёт чистое перебазирование при переносе runtime-отметок и не вычитает срок второй раз. Отдых не меняет формат данных и сам по себе не создаёт единую временную ось путешествий и сохранённых локаций.

## Опыт и уровни

`hero.level` и `hero.xp` ведёт движок: из ответа мастера они не применяются, только из сохранения (`Storage.ApplySavedState` — загрузка, MCP, герой библиотеки). Мастер начисляет опыт патчем `hero.xpAward` (`monsters` — `monsterKey` побеждённых, опыт по уровню опасности; `xp` — за прочее); итог и «доступен новый уровень» движок пишет в историю после ответа. Таблица правил — `src/GameData/DnD5e_levels.json` (`LevelRules`): пороги, бонус мастерства, кости хитов, уровни улучшения характеристик. Стат «Класс» — без уровня (`ClassLevel` отрезает «3 ур»).

«Новый уровень» (`LevelUpDisplay`, F10 или кнопка на карточке, вне боя) — панель на вкладке «Персонаж» вместо диалога: карточка сверху показывает героя после повышения (`HeroDisplay.Preview`, изменения золотым), в блоке картинки — карточка заклинания из справочника или описание пункта. Свободного ввода в лист нет: код считает хиты (среднее или один бросок), бонус мастерства и улучшение характеристик; `LevelUpOptions` возвращает полученное и группы выбора, строка ввода — просьба о своём варианте (тот же промпт, только по правилам класса и уровня, вариант «★» или отказ); `LevelUpApply` — патч листа по выбору. `LevelUp.Apply` собирает нового героя на копии: из патча — только статы, навыки, умения, ресурсы, заклинания, поверх — числа движка. «Принять» заменяет героя, отмена ничего не меняет. Варианты мастера и бросок хитов хранятся в сохранении (`hero.levelUpDraft`, только движок): отмена, выход в меню и перезапуск не запрашивают их заново и не дают перебросить хиты.

## Карты и время

Локации строятся блоками: мастер задаёт план через `plan_location`, геометрию строит код, следующие блоки наполняет `PopulateChunk`. На расстоянии 10 клеток запускается один фоновый запрос; на расстоянии 4 клеток игра ждёт его, если он ещё не готов. Запрос читает отдельный временный снимок через MCP, общий семафор не допускает одновременных запросов с ходом мастера. Очередь возвращает данные без изменения состояния: игровой цикл проверяет актуальную локацию, клетки, символы и границы блока, затем применяет только добавления объектов/существ и допустимые изменения комнат. Смена локации отбрасывает старый результат; ошибка не вызывает повторного запроса на каждом шаге. Перед следующим ходом мастера ожидается и применяется уже начатое наполнение. Есть подземелья, пещеры и открытая местность. Без тактической локации F1 показывает цветную иллюстрацию текущего места; F2 открывает карту мира и маршруты. Галерея F11 сбрасывается при смене места или появлении тактической карты.

Открытая местность формируется связными рощами, полянами, осыпями и берегами; тропы выбирают свободные клетки и соединяют выходы через меняющуюся точку, изолированные участки получают короткие проходы. Геометрия уже сохранённых локаций не меняется. Расчёт пути NPC и героя запрещает обход препятствий через пустоту за пределами построенной геометрии; скрытые объекты и двери требуют прямой видимости для `onVisible`.

`WorldLibrary` хранит геометрию и хронику мира. Изменение хроники сбрасывает кэш представлений всех героев этого мира; добавленное место доступно для перемещения уже в том же патче. `GameWorld` связывает её со знаниями героя. `TravelService` рассчитывает путь, время и встречи; мастер получает сводку. При переходе календаря сроки героя и переносимых вещей сдвигаются в новую локальную шкалу: дорога не продлевает защиту. Истёкшие callbacks сохраняются для разрешения, прибытие само по себе не считается отдыхом. Ночью ближайшее утро относится к тому же календарному дню. Подробнее: [world-map.md](world-map.md).

`LocationRestoration` выбирает свободное место у входа до применения сохранённой карты: возвращение не сдвигает жителей и не ставит героя поверх NPC. При заблокированном входе снимок остаётся нетронутым, мастер описывает прибытие снаружи. Смена локации сбрасывает привязанные к символам сведения об обнаружении и реакциях.

Формат 7 добавляет в атомарный снимок локации `snapshotTime` (день, часть суток, раунд). При возвращении сроки эффектов существ и объектов пересчитываются с учётом отсутствия героя; пропущенные `onRound` не проигрываются и отдых не начисляется. Истёкшие `onExpire` сохраняются для однократной обработки через `RoundBundle`, включая объекты карты. Более ранний календарь другого героя не увеличивает оставшийся срок. Миграция сохраняет резервную копию и ставит старым снимкам `snapshotTime: null`: неизвестную дату нельзя восстановить, поэтому их сроки остаются прежними до следующего сохранения. Это метаданные архива, не поле модели карты, AI-патча или MCP-контекста.

`ExplorationMemory` хранит исследованные клетки и замеченные предметы отдельно для каждой локации и каждого сохранения героя. Ключ включает мир, место (для безымянных встреч — координаты) и первый сид геометрии; расширение карты сохраняет память, новая генерация её не наследует. Файл `*.explored.json` формата 5 содержит `locations` с `cells` и `seenObjects`, записывается атомарно и не передаётся мастеру через JSON/MCP. Миграция привязывает прежний массив клеток только к текущей тактической карте и сохраняет исходник в backup; старый формат не доказывает знание предметов. Без тактической карты или связанного сохранения старые клетки остаются только в backup, чтобы не раскрыть следующее место.

`TakeRoundBundle` объединяет эффекты и события начала раунда. Боевые перемещения рассчитывает `calculate_movement`, решения врагов принимает мастер. Правила боя находятся в `SendAction/systemPrompt.md`.

## Файлы

- `src/NaviDnD/Prompts/{RuleSet}/{Action}/systemPrompt.md` — инструкции мастера.
- `src/GameData`, `src/icons`, `src/NaviDnD/sound`, `src/NaviDnD/Fonts` — ресурсы приложения.
- `src/NaviDnD/Storage/settings.json` — настройки; `gameN.json` — сохранения; рядом — туман войны и заметки.
- `Storage/Worlds`, `Heroes`, `Portraits` — личные библиотеки; `logs` — диагностика. Всё это исключено из Git.

Каталоги и настройки создаются при первом запуске; остальные данные — по мере использования. Пустой запуск не создаёт фиктивную сохранённую игру. Миграция старых сохранений сохранена.

`AppConfig.ProjectRoot` определяется по текущей сборке: при запуске из исходников данные находятся в игровом проекте, при тестировании логики — в тестовом. Настройки Codex: [codex.md](codex.md). Проверки: [testing.md](testing.md).
