# План: английский язык и выбор языка

Цель — выбор языка в настройках (русский/английский) для интерфейса, ответов мастера, справочников и озвучки. Русский остаётся языком по умолчанию; существующие сохранения продолжают работать.

## Исходное состояние

- Около 1100 строковых литералов с кириллицей в ~60 файлах. Больше всего — `SettingsDisplay`, `NewGameDisplay`, `NewGameWizard`, `AiContextBuilder`, `HeroDisplay`, `TravelService`, `GameAiClient`, `JournalDisplay`, `MonsterCard`; также установщик (`NaviDnD.Installer`) и MCP-сервер.
- Промпты `Prompts/Dnd5e/*` написаны по-русски; ответы мастера и генерация мира — на русском.
- Русские строки используются как идентификаторы: имена характеристик (`"Класс Доспеха"`, `"Раса"`, `"Класс"`), автор `"Герой"`, расы и классы в `heroOptions.json`, метки в контексте ИИ (`да`, `ур.`, `фт`).
- Справочники `GameData/DnD5e_*_BD.dtn` уже содержат `en` и `ru`; поиск идёт по русскому имени.
- `DialogHighlighter` подсвечивает урон, лечение и исход броска русскими регулярными выражениями и учитывает падежи.
- Озвучка — русская модель Silero `v5_5_ru.pt` с русскими голосами.

## Ключевое решение: язык интерфейса и язык мира

- **Язык интерфейса** — настройка `Language` в `AppConfig`, переключается в любой момент.
- **Язык мира** записывается в мир при создании и не меняется: имена, описания, журнал и история уже сгенерированы на нём. Новый мир по умолчанию берёт язык интерфейса. Старые сохранения без поля считаются русскими.

Так не придётся переводить сохранённый текст, а смена языка не ломает идущую игру.

## Этапы

### 1. Инфраструктура и настройка — сделано

- `L` (`NaviDnD.Data/L.cs`): ключ перевода — русская строка из кода, `L.T("НАСТРОЙКИ")`, шаблоны — `L.F("День {0}", day)`, числа — `L.Plural(n, "день", "дня", "дней")`. Английский — `NaviDnD.Data/Localization/en.json` (встроен в сборку); нет перевода — русская строка. Отдельный `ru.json` и искусственные ключи не нужны: русский текст остаётся в коде на месте.
- `AppConfig.Language` (`"ru"`/`"en"`, в `settings.json`), пункт **ЯЗЫК** в настройках — пункты и заголовок перестраиваются сразу, остальные экраны — со следующей отрисовки.
- `WorldMap.Language` — язык интерфейса при создании мира; `null` у старых миров — русский. Пока только записывается (используется на этапе 4).
- `LocalizationTests`: у каждой строки из `L.T/L.F/L.Plural` есть перевод, подстановки `{0}` совпадают, ключи — обычные литералы (не `$"…"`), справочные названия (биомы, типы мест, рельеф, мебель, стороны света, части суток) переведены.

### 2. Перевод интерфейса — сделано

- Переведены меню, настройки, обновления, «Мои игры», мастер новой игры, анкета героя, лист персонажа, журнал, карточки монстров и заклинаний, легенда и подсказки карты, диалог и броски, сообщения об ошибках ИИ и озвучки, установщик.
- **Граница:** переводится только то, что видно на экране и не сохраняется, плюс системные подсказки в диалоге («Путь преграждён», «Идёт бой — уйти в путь нельзя»). Текст, который уходит мастеру или хранится как часть истории (контекст ИИ, сводка пути, реплики героя «Завершаю ход», «Ты спускаешься по лестнице», результат выбора цели), — на языке мира, то есть пока по-русски. Для общих функций — пары: `MapConfig.FloorName` (мастеру) и `FloorLabel` (экран), `TravelService.PaceName` и `L.T(...)` при показе, `DaysLabel`.
- Данные героя и мира (раса, класс, характеристики, навыки, названия мест, значения из справочников монстров и заклинаний) показываются как есть — их язык меняется на этапах 3–5.
- Установщик: язык — из `Storage/settings.json` установленной игры, иначе из языка Windows. Свой словарь `NaviDnD.Installer/en.json` (только его строки, тест сверяет с игрой) — чтобы правки текста игры не пересобирали установщик; `NaviDnD.Data/L.cs` входит в отпечаток исходников установщика (`build-release.ps1`).

### 3. Стабильные идентификаторы вместо русских строк

- Расы, классы, предыстории в `heroOptions.json`: добавить `id` и названия `ru`/`en`; в героя записывать `id`, отображать по языку.
- Характеристики (`Класс Доспеха`, `Раса`, `Класс`) и автор `Герой` — константы-идентификаторы, отображаемое имя — из словаря.
- Миграция при загрузке: русские значения старых сохранений сопоставляются с `id`.
- Метки контекста ИИ (`да`, `ур.`, `фт`) перевести в нейтральные машинные (`true`, `lvl`, `ft`): модели они понятны независимо от языка, а контекст становится короче.

Этот этап — основной риск регрессий: проверить `Storage.Apply*`, `AiContextBuilder.Serialize`, ключи MCP и существующие тесты.

### 4. Язык ответов мастера

- В контекст запроса — одна строка `lang:en|ru` из языка мира.
- В каждый системный промпт — одно правило: весь текст для игрока (реплики, имена, описания, журнал) — на языке `lang`; JSON-ключи и механика не меняются.
- Промпты остаются в одном экземпляре. Отдельный английский комплект промптов делать только если тесты покажут смешение языков в ответах.
- Примеры в `response*.json`: проверить, что русские примеры не тянут модель в русский при `lang:en`.
- Сообщения MCP-инструментов предназначены модели, их можно не переводить; пользовательские тексты из MCP (если есть) — по языку мира.

### 5. Справочники

- `SpellDatabase`, `MonsterDatabase`, `EquipmentDatabase`: индексировать по обоим именам, отображать по языку мира.
- Поиск предметов и заклинаний, которые называет модель, — по любому из двух имён, чтобы английский ответ находил запись.

### 6. Подсветка диалога

- `DialogHighlighter`: набор регулярных выражений на язык (урон и типы урона, лечение, hit/miss, success/failure).
- Сопоставление имён существ для английского — без падежных окончаний (точное совпадение и множественное число).

### 7. Озвучка

- Русская модель Silero не читает английский. Варианты:
  - **на первом этапе** — при английском мире озвучка недоступна, в настройках показывается пояснение;
  - позже — английская модель Silero (`v3_en`) с отдельным списком голосов. Она увеличит базовую сборку, поэтому её нужно ставить отдельной загрузкой по запросу, а не в основной payload.
- Голоса и тестовая фраза («Добро пожаловать.») — по языку.

### 8. Документация и релиз

- `README.en.md`, английский раздел в `RELEASE_NOTES.md`, обновить описание релизов на GitHub (убрать предупреждение «Russian only»).
- Выпуск — обычным патчем; новые словари и `heroOptions.json` попадают в патч как изменённые файлы.

## Проверки

- `dotnet test NaviDnD.Tests/NaviDnD.Tests.csproj` на каждом этапе; новые тесты: полнота словарей, миграция старых сохранений, загрузка героя по `id`, подсветка английских строк.
- Ручной прогон: новая игра на английском от создания персонажа до первого боя; загрузка старого русского сохранения при английском интерфейсе.
- Точечные `PromptTests` с `lang:en` (тратят лимиты, запускать выборочно): нет русского текста в ответе, механика и JSON не меняются.

## Порядок и объём

Этапы 1–2 дают переключаемый интерфейс и могут выйти отдельным релизом. Этапы 3–5 — английская игра целиком, выпускаются вместе. Этапы 6–7 — доводка. Самые трудоёмкие — перенос строк интерфейса (2) и стабильные идентификаторы с миграцией (3).
