# Библиотека изображений V2

Портреты NPC берутся из локальной галереи и закрепляются в сохранении; карта и журнал
показывают одинаковое лицо. В пиксельном паке клетки используют соответствия `terrain`,
а не только старые SVG-значки. Именные дополнения (чаща, благовония) и семейства спрайтов
NPC находятся в `RuleSets/Dnd5e/runtime-additions.json`; экспорт — `scripts/prepare-runtime-art.py`.
Для оставшихся SVG в пиксельном паке используется силуэт полублоками с цветом объекта.
Это резервная отрисовка, не новая цветная иллюстрация; заклинания сохраняют цветной Брайль.

В HTML-каталоге блок **«Подобрано по разделам»** показывает число потребностей с доступной
картинкой и общее число потребностей в каждом разделе. Нажатие открывает соответствующий
раздел. Счётчики не зависят от поискового фильтра и обновляются при отклонении или удалении
картинки. Наличие подбора не означает художественное одобрение.

Названия показываются на двух языках: **English — Русский**, в том числе в просмотре
картинки и у аналогов заклинаний BG3. Поиск работает на обоих языках. Переводы берутся из
игровых справочников и локализации; подписи дополнительных категорий — из
`scripts/art_catalog_names.py`. Английские ключи соответствий и пользовательские оценки
не меняются. Технические имена ресурсов без известного перевода сохраняются как есть.

## Контурные иконки заклинаний BG3

Подготовлены 284 соответствия заклинаний иконкам BG3: [слои PNG](Sources/bg3-spells/),
[соответствия заклинаниям](RuleSets/Dnd5e/spell-icons.json),
[отчёт о покрытии](RuleSets/Dnd5e/spell-icon-coverage.json).
В базе 539 записей и 535 различных английских названий. Закреплены 211 оригинальных
соответствий и 73 аналога по смыслу для заклинаний, которых нет в BG3. Для остальных
251 названия соответствие ещё не подготовлено, поэтому сохраняется прежний подбор.
Если заклинание есть в BG3, используется его собственная иконка, включая общий
значок для заклинаний с несколькими вариантами призыва. «Погребальный звон» добавлен
из более нового набора BG3: [исходник 64×64](Sources/bg3-spells-supplemental/toll-the-dead.webp).
Источник, тип совпадения (`exact` / `thematic`) и обоснование сохранены в манифестах;
аналоги явно отмечены в галерее и в разделе соответствий.

Этот формат используется **только в карточках заклинаний**. Подмены инвентаря убраны.
В `spell-icons.json` закреплены постоянные ID картинки, русские/английские названия
и словарные варианты. И пиксели, и Брайль используют один ID; смена пака не подбирает
другой рисунок. Учитываются регистр, лишние пробелы, `ё/е` и типографский апостроф;
неизвестное имя не привязывается по похожим словам.
Если синоним совпадает с основным названием другого заклинания, основное название
имеет приоритет. Подготовка проверяет неоднозначные имена до записи манифеста.

Сборка галереи (`python scripts/audit-art-catalog.py`) синхронизирует эти же именные
соответствия с `requirement-bindings.json` и разделом «Что нужно игре», затем
пересчитывает общие счётчики и покрытие по категориям. Для закреплённых заклинаний
прежние подборки заменяются одной иконкой BG3; прочие соответствия сохраняются.
Удалённые и отклонённые пользователем изображения не учитываются как доступные.

**В блоке «Заклинания» всегда используется цветной Брайль**, независимо от выбранной
техники отрисовки, общего пака и `defaultRenderMode` в манифесте. Для заклинаний без
подготовленных слоёв применяется SVG в Брайле с цветом заклинания. Пиксельные версии
сохраняются для библиотеки и отдельных вызовов конвертера, но карточки игры их не используют.
Цвет **названия** в списке и карточке берётся из `nameColor` —
основного цвета штрихов; описание, характеристики и фон от него не перекрашиваются.
Эта привязка применяется и к обычным выученным заклинаниям, не только к просмотру.
На Windows и macOS подготовка одинаковая: `python scripts/prepare-bg3-spells.py`
(Python 3.10+, Pillow, py7zr; на macOS обычно `python3`). Архив по умолчанию лежит
в корне проекта; другой путь задаётся через `--archive`. Повторный импорт проверяет
хеши и не перезаписывает вручную изменённые изображения. Интернет для него не нужен.

Подготовка выполняется один раз, а не перед каждым запуском игры:

- `*.original.png` — исходная ячейка атласа 64×64.
- `*.mask.png` — чёрные точки будущих линий на белом фоне.
- `*.color.png` — цвет каждой точки линии; маска сама цвета не содержит.
- `*.background.png` — нейтральная подложка с мягкими краями.
- `*.pixel.png` — ровно 32×32 для вывода полублоками; цвет тонких линий не смешивается с фоном.

Для «Темновидения» и «Тьмы» закреплены отдельные параметры: более низкий порог,
голубая палитра и усиление яркости без смены оттенка. Они сохраняют кольцо глаза
и спирали, которые терялись при общем пороге.

Очистка палитры удаляет тусклые цветные вкрапления текстуры, которые не относятся
к цветам ярких штрихов: например, коричневые точки под голубой молнией Witch Bolt.
Настоящие оттенки линий не перекрашиваются; многоцветные символы и золотая магия
сохраняются. Для отдельной картинки этот этап включает `--clean-palette` у
`scripts/icon_to_braille.py`; пакетный импорт применяет его автоматически.

Игра собирает символы Брайля из маски, усредняет цвета активных точек внутри каждого
символа 2×4 и отдельно накладывает фон. Область — 36×18 символов; рисунок не растягивается.
Слои и манифест включаются в сборку, правила и личные сохранения не меняются.
Для временной проверки все 284 соответствия сразу доступны в **Персонаж (F4) → Заклинания (F9)**,
даже если герой ещё не знает заклинаний. Переключателя нет. Выбор — мышью или Tab / Shift+Tab,
страницы списка — стрелками. Кружок `•` перед названием обозначает подготовленное
заклинание; у добавленных для просмотра строк его нет. В карточке показаны название,
круг и школа без служебной подписи. Настоящие заклинания не дублируются и сохраняют подготовку и свойства.
Это только список интерфейса: заклинания не выдаются герою и не записываются в сохранение.
Инвентарь не меняется. Иконка находится на первой странице карточки.
В [галерее BG3](http://127.0.0.1:8765/artifacts/art-catalog-review/index.html#bg3)
показываются PNG с цветными линиями, без текстового Брайля.
Это отдельный формат контурных ресурсов, не пиксельные изображения 32×32 из общего каталога.

Позиции в атласах закреплены в `RuleSets/Dnd5e/bg3-spell-sources.json`: именные
64×64 образцы BG3 Wiki сопоставлены по изображению с ячейками вашего архива.
Происхождение и ограничения исходных ресурсов указаны в манифесте.
Проверено на Windows; нативный запуск на macOS ещё не проверен.

**Генерация: только настоящий пиксельный рисунок 32×32.** Большие иллюстрации
с имитацией пикселей и их уменьшенные копии не подходят. Перед добавлением в
каталог обязательны [критерии генерации и проверки](GENERATION.md).

## Единственная рабочая библиотека

Все окончательные импортированные изображения находятся здесь, в `Sources/`.
Собственные изображения хранятся отдельно в [`Sources/own-art/`](Sources/own-art/README.md); рядом с PNG записываются происхождение и SHA-256.
`python scripts/audit-art-catalog.py` добавляет их в HTML-галерею (пак «Собственные изображения», раздел «Лица»); `save-art-library.py` включает их в черновик каталога.

Единственная галерея для просмотра и разметки —
`http://127.0.0.1:8765/artifacts/art-catalog-review/index.html`.
Её `imported/*/icons` — восстанавливаемый рабочий кэш для просмотра и удаления,
а не ещё одна коллекция для ручного ведения. Существующий игровой DCSS остаётся
в `src/icons/dcss`, поскольку на него ссылается игра. V1 и `000000` не меняются.

`prepared-assets.json` и `prepared-packs.json` описывают дополнительные извлечения
из превью, отдельно от исходных авторских PNG в `packs.json`. Они имеют выходной
размер 32×32, но не объявлены оригинальными PNG: палитра после JPEG не восстановлена.
Все 4080 дополнительных ресурсов просмотрены по отдельности на 85 нумерованных
листах и описаны в `prepared-annotations.json`. Воспроизводимый источник описаний —
`scripts/describe-prepared-art.py`: он проверяет количество 48 на лист и хеши PNG.
Описание привязано к точным байтам и не устанавливает пол, происхождение персонажа,
магический эффект или класс. Пользовательская разметка накладывается отдельно.
Художественное одобрение этих ресурсов ещё не выполнено;
строгий подборщик их пока не выбирает. Извлечённые полурослики из исключённого
64px семейства не импортированы.

`ExtractionSources/` содержит исходные превью, скрипты извлечения и их манифесты.
Промежуточные галереи и экспорты в отдельных папках `artifacts` удалены после
проверки сохранённых PNG. `consolidation-report.json` фиксирует очистку.

`reviews.snapshot.json` сохраняет пользовательские отметки; неизменённый экспорт
также сохранён в `ReviewBackups/`. Экспорт `artifacts/art-review.json` подхватывается
при сборке. Пол переносится по ID и совпадающему хешу, старый ID допускается только
при однозначном совпадении хеша. Разметка пола сама по себе не одобряет картинку.
В текущем экспорте 100 записей, но 99 различных портретов: один орк отмечен под
двумя ID, у остроухого портрета №6 пол остаётся неизвестным.

После очистки восстановить кэш и пересобрать общую галерею можно так:

```sh
python scripts/import-art-packs.py
python scripts/import-prepared-art.py
python scripts/describe-prepared-art.py
python scripts/save-art-library.py
python scripts/audit-art-catalog.py
```

Общий код работает с путями Windows/macOS; эта очистка и проверки выполнены на Windows.

Для всех 4794 импортированных кандидатов есть описания видимого содержимого.
Также просмотрены и описаны все 4704 файла DCSS из зафиксированного набора:
98 нумерованных листов по 48 увеличенных спрайтов. `dcss-review-index.json`
сохраняет порядок и хеш каждого изображения; `dcss-annotations.json` — описания,
тип композиции и предложения об исключении; `dcss-description-coverage.json` —
актуальные пропуски. Кадры одного эффекта могут иметь общее описание с указанием
вариантности. Обзор или описание не означают художественного одобрения.

В галерее раздел **«На согласование исключения»** показывает предложения с причинами.
**«Оставить»** сохраняет положительную пользовательскую отметку и убирает ресурс
из ожидающих решения; **«Удалить PNG»** действительно удаляет рабочий файл, как прежде.
Скрипт описания ничего не удаляет, отметки пола и пользовательские замечания не меняет.
Для старого работающего сервера решения нужно экспортировать, как остальные отметки.

Для создания персонажа в V2 подбирается готовое лицо или голова с плечами 32×32
с назначением `portrait`. Сборка персонажа из тела, одежды и экипировки в этот
сценарий не входит. Подходящих лиц может быть несколько; выбор учитывает известные
признаки и занятость семейства, затем закрепляется за персонажем. Отсутствующее
лицо остаётся пробелом подбора, а смена экипировки не меняет портрет.

Старый `HeroDoll.Render` и его слои пока сохраняются как часть существующей игры;
это не план конструктора персонажа V2. Сохранение компонентов в библиотеке
не означает обязательного использования при создании персонажа.
Изначальные верх/низ высоких существ были отмечены отдельно: исходное семейство
DCSS использует полотно 32×48. Основание —
[определения больших существ](https://github.com/crawl/crawl/blob/0.16.2/crawl-ref/source/rltiles/dc-mon.txt)
и [компоненты демонов](https://github.com/crawl/crawl/blob/0.16.2/crawl-ref/source/rltiles/dc-demon.txt).
Для проверки дополнительно сверены исходные PNG 32×48; верхняя часть головы-мозга
пиксельно совпала с исходником. Точный исходный размер каждого исторического варианта
не заявляется: `documentedFamilyCanvas` относится к проверенному семейству.

После ручной проверки пользователь удалил ненужные ресурсы, включая нижние части,
и явно оставил остальные. `retention-decisions.json` сохраняет 104 таких решения,
привязанных к хешам. Они имеют приоритет над прежними предложениями: пересборка
не возвращает сохранённые ресурсы в очередь исключения. Решение «оставить» само
по себе не означает художественного одобрения для любого применения.

Оставшиеся верхние компоненты разрешено накладывать внутри одного холста 32×32.
`composition-examples.json` содержит четыре проверенных примера: крылья → тело →
голова, без перемещения, масштабирования или восстановления удалённого низа.
`python scripts/render-art-compositions.py` воспроизводит PNG 32×32 в кэше просмотра,
проверяя размеры и хеши входных слоёв. Это примеры композиции, не назначения в игре.

Повторная подготовка не сдвигает прежние позиции и не возвращает удалённые PNG:

```sh
python scripts/prepare-dcss-review.py
python scripts/describe-dcss-art.py
python scripts/audit-art-catalog.py
```

Новые файлы добавляются в конец индекса и остаются без подтверждённых описаний
до следующего просмотра. Изменённые байты под старым ID требуют нового просмотра.
Сопоставления «Что нужно игре» заполняются после просмотра используемых кандидатов;
одно требование сможет иметь несколько картинок, и одна картинка — несколько
подходящих применений. Отсутствие соответствий пока не является нехваткой файлов.

Текущий набор находится в `RuleSets/Dnd5e/requirement-bindings.json`: 612 потребностей,
4489 связей с изображениями из новых паков и проверенными вариантами DCSS — снаряжение, заклинания, существа, окружение и
магические предметы. Это явные соответствия по категории и
английскому имени справочника, без поиска по названиям файлов и без привязки к
меняющемуся порядковому номеру. У кандидата зафиксированы ID, хеш, назначение и
обоснование. Удалённые/изменённые/отклонённые ресурсы не заменяются произвольными.
Подготовка: `python scripts/prepare-art-requirement-bindings.py`, затем сборка галереи.
В разделе «Что нужно игре» видны все миниатюры кандидатов с увеличением по нажатию.
По умолчанию показаны потребности с вариантами; фильтр также показывает все
потребности или только незаполненные. При увеличении видны название потребности,
обоснование соответствия и описание самой картинки. Оценка потребности привязана
к хешу её набора кандидатов: изменённая подборка не наследует старое одобрение.
Варианты подготовлены для дальнейшего балансируемого выбора с закреплением образа;
игровая интеграция и художественное одобрение этим не подменяются. Предметные
свойства, которые не видны на иконке (длина/материал верёвки, заклинания книги),
задаются игровыми данными, а не угадываются из внешности. Для заклинаний подбирается
узнаваемый мотив, а не переносится механика исходной способности из пака. Для
магических предметов подтверждается форма, но не скрытые свойства и редкость.

Для конкретного магического предмета с точно подходящим особым обликом оставляется
одно изображение: `selectionPolicy.mode = exclusive_exact`, `match = exact` и
обоснование видимого соответствия. Его ID и SHA-256 резервируются за этой
потребностью во всём списке: проверка запрещает повторное использование даже
под другим ID. Обычная форма кольца, книги или посоха сама по себе не означает
точного совпадения. Пока такое соответствие не подтверждено, варианты остаются
черновыми; это правило не делает все обычные предметы уникальными. Повторные
экземпляры одного и того же типа магического предмета используют его же образ.

DCSS допускается как запасной источник: `sourcePriority` равен 0 для новых паков
и 1 для DCSS, после проверки смыслового соответствия и совместимости стиля.
`reviewed-usages.json` явно подтверждает назначение выбранных DCSS-файлов по ID
и SHA-256; остальные файлы не получают назначение автоматически. Это метаданные
офлайн-подборки, игровой выбор ещё не подключён. Открытая и закрытая дверь —
варианты состояния, а не случайные взаимозаменяемые картинки.

Это постоянные исходники и черновик каталога, а не включённый режим игры. Архитектура: [docs/art-v2.md](../../docs/art-v2.md).

`Sources/` хранит оригинальные PNG, PSD, варианты с фоном и без, лицензии и README из предоставленных паков. `packs.json` фиксирует происхождение и SHA-256. Исходники не подключены к публикации игры целиком: PSD и альтернативные варианты не должны попадать в игровой пакет автоматически.

`catalog.draft.json` содержит выбранные PNG 32×32, включая отдельно помеченные извлечения из превью. Статусы технической проверки, описания содержимого и художественного одобрения разделены. Черновик загружается `ArtCatalog.Parse`; пока `artApproved` выключен, подборщик не выдаёт эти ресурсы как одобренные.

Полурослики 64×64 исключены в `excluded-packs.json`, уменьшенные версии также не используются. `deletions.snapshot.json` — снимок исключений пользователя на момент сборки. Живой журнал удаления находится в `artifacts/art-catalog-review/deletions.json`; перед удалением всей папки `artifacts` обновите снимок командой сохранения библиотеки. Личные замечания экспортируйте из браузера.

## Подготовка и проверка

Для террейна добавлены пять оригинальных PNG 32×32 GwizTiles: трава, песок,
снег, вода и горизонтальный каменистый путь. Источник — David Gwizdala,
https://gwizkid.com/GwizTiles/, лицензия CC BY 4.0. Атрибуция, исходный README
и точная ревизия сохранены в `Sources/gwiztiles`; `external-assets.json`
фиксирует хеши и описания. PNG не масштабировались. Деревья этого пака имеют
размер 16×16 и в каталог не включены. Непрозрачность поверхности земли намеренная;
объекты и накладки используют прозрачность. Загрузка учитывает пользовательские
удаления и отказывается перезаписывать изменённый кэш. Подбор террейна не заменяет
отдельные виды локаций; соединение дорог и смешивание стилей ещё требуют проверки в игре.

Команды выполняются из корня репозитория. Нужен Python 3.10+ и Pillow; на macOS команда может называться `python3`. Скрипты используют общий код для Windows/macOS и не обращаются к моделям.

```sh
python scripts/describe-art-packs.py
python scripts/import-art-packs.py
python scripts/audit-art-dependencies.py
python scripts/audit-art-catalog.py
python scripts/save-art-library.py
```

Новые архивы `craftpix*.zip` кладутся в корень. Импорт сохраняет все исходные файлы, проверяет пути и хеши, связывает варианты. Неизвестные паки остаются неклассифицированными до просмотра; назначение не угадывается по слову `avatar`. Поле `unknown` не подтверждает пол, вид или другой обязательный признак.

После удаления ZIP импорт может читать сохранённые исходники. Если папка просмотра потеряна, `import-art-packs.py` использует `packs.json` этой библиотеки. Пользовательские удаления из доступного журнала или снимка не восстанавливаются. Изменённые вручную исходники и PNG не перезаписываются молча.

Пак `000000` инструменты V2 не обходят и не изменяют. `validate-pixel-library.py` нужен для отдельной технической проверки текущего DCSS и сборки контактных листов; он не восстанавливает удалённые файлы и не одобряет картинки автоматически.

## Каталог в браузере

Галерея создания героя задаётся отдельно в `portrait-gallery.json`: 171 проверенное
изображение лица или головы с плечами, без фигурок для карты. Она не назначает
персонажу пол или профессию по внешности; лицо выбирает игрок. Поле `portraitGroup`
в `heroOptions.json` ограничивает только пиксельные портреты группой выбранной расы: люди, эльфы,
дроу, дварфы, орки или гоблины. GAME-ICONS сохраняет общий выбор лиц без ограничения по расе. Для отсутствующей пиксельной группы — нейтральный знак вопроса;
полурослики и гномы используют общую подборку из 48 лиц выбранного пользователем пака.
Она извлечена по пиксельной сетке из сохранённого увеличенного JPG-превью;
палитра оригинального PNG не восстановлена. Полуэльфы используют подборку эльфов,
полуорки — подборку орков. Для тифлингов отобраны 12 простых гуманоидных лиц из пака демонов.
Кенку и ящеролюды исключены только из новых анкет. Пользовательские
портреты и изображения уже сохранённых героев сохраняются.

«Свои генерации · 32×32» (`#generated`) содержит собственные сгенерированные
изображения. Большой результат image_gen — только исходник, а не готовый игровой
ресурс. `scripts/prepare-generated-icon.py` сохраняет его отдельно в
`Sources/own-art/generation-sources`, делает итоговый RGBA PNG ровно 32×32
без сглаживания, проверяет размер и записывает преобразование в provenance.
После подготовки рисунок проверяется в натуральном размере и при целочисленном
увеличении. Плохой результат не исправляется одной надписью «pixel art»:
нужно менять композицию и крупность деталей в генерации.
Подробный промпт: `Sources/own-art/pixel-generation-prompt.txt`.
Медный драконорождённый — первый портрет этого процесса; его глаз сохранён без
сокращения палитры. Наличие 32×32 пикселей проверяется отдельно от качества рисунка.

Партия `hundred-20261107` добавляет 100 проверенных изображений и 100 новых
сопоставлений: 19 предметов, 10 видов мест, 12 видов биомов и 59 существ.
Все итоговые PNG имеют размер 32×32, не более 20 видимых цветов и бинарную
прозрачность; пейзажи непрозрачны. План, точные промпты каждого вызова и решения
проверки сохранены в `Sources/own-art/generation-batches/hundred-20261107/`.
Вариант морского конька `v1` отклонён из-за посторонней полоски, опубликован `v2`.
`python scripts/verify-generated-batch.py` проверяет все 100 файлов, хеши,
сохранённые исходники и реальные назначения в игровом `runtime-pictures.json`.
Отчёт проверки: `artifacts/art-completion/hundred/delivery.json`.

`python scripts/prepare-runtime-art.py` после пересборки каталога упаковывает
проверенные сопоставления и галерею в `Runtime/Images` и
`RuleSets/Dnd5e/runtime-pictures.json`. Игра использует одни и те же изображения
для известных названий предметов, ответов модели, MCP и карточек. Сопоставления
не означают полной готовности всех разделов: счётчики показывают оставшиеся пробелы.
Лицензии и происхождение поставляются вместе с ресурсами; заклинания сохраняют
отдельный режим цветного Брайля.

Раздел **«Новые изменения»** (`#changes`) показывает добавленные, изменённые и
удалённые подборки с миниатюрами текущих кандидатов и списком изменённых ID.
Выбор порции позволяет вернуться к предыдущим изменениям. История хранится в
`change-history.json`, начиная с последних 26 добавленных потребностей; более
ранние изменения не отслеживались. Пересборка без изменений не добавляет событий.
История относится к подборкам «Что нужно игре», а не ко всем изменениям файлов.

```sh
python scripts/serve-art-review.py --port 8765
```

Открыть: `http://127.0.0.1:8765/artifacts/art-catalog-review/index.html`.

Кнопка **«Удалить PNG»** немедленно удаляет показанный рабочий файл и записывает исключение, без подтверждения. Архивные оригиналы и лицензии сохраняются отдельно для происхождения и ручного восстановления; повторный импорт не возвращает исключённый ресурс в подборку. Пак `000000`, личные сохранения и произвольные пути API удалить не может.

Новый сервер сохраняет отметки в `reviews.json`, привязывая их к хешу изображения. Экспорт/импорт JSON также доступен. Уже запущенная ранняя версия сервера поддерживает удаление и хранение отметок в браузере; для неё нужен экспорт. Файл `server-session.json` относится только к локальной сессии в игнорируемой папке `artifacts`, не к данным библиотеки.

Не запускайте одновременно два пишущих сервера над одним каталогом. HTML, открытый как `file:///...`, предназначен для просмотра и экспорта: прямое удаление файлов из него отключено.

## Проверки

```sh
dotnet test src/NaviDnD.Tests/NaviDnD.Tests.csproj
python scripts/test-art-review-server.py
python scripts/test-art-review-browser.py
python scripts/test-art-import.py
```

Браузерная проверка использует отдельную временную папку и копию PNG, проверяет сохранение замечаний и реальное удаление кнопкой; рабочую библиотеку не удаляет. Нужны Chrome/Chromium и пакет `websocket-client`; путь можно указать через `--chrome`. Проверено на Windows. Прогон на настоящем macOS и визуальная проверка в игровом терминале ещё не выполнены.

Полный .NET-прогон может выявлять ссылки старой игры на удалённые при чистке ресурсы. Исправлять следует таблицы/назначения при переходе на V2, сохраняя пользовательский выбор; нельзя отключать проверку или возвращать удалённые файлы ради зелёного теста.
